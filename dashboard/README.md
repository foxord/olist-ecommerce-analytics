# Отчёт Olist

Для готовой интерактивной версии откройте index.html в браузере из распакованной папки. Вкладки [Обзор](overview.png), [Клиенты](customers.png) и [Логистика](delivery.png) используют общий выбор месяца, штата и категории. При выборе категории оборот включает её позиции, а заказ и клиент считаются по одному разу. Сегмент RFM закреплён за покупателем по всей истории.

Отчёт хранит производную модель с месячной детализацией даты покупки, целыми суммами в сентаво и внутренними номерами покупателей. Для обновления из корня запустите `python dashboard/export.py`. Источник — [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce). Экстракт распространяется по [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/).

## Как воспроизвести модель в Power BI Desktop

Через **Получить данные → PostgreSQL** импортируйте olist.order_mart под именем Orders, оставив delivered. Импортируйте строки olist.order_items под именем Items. В Power Query присоедините к Items таблицу products по product_id и category_translation по product_category_name (левые соединения). При пропуске перевода используйте исходную категорию, а при пропуске обеих — unknown. Задайте связь Orders[order_id] → Items[order_id] как один ко многим. Для среза категории примените фильтрацию в обе стороны по этой единственной связи. Для денег используйте фиксированную десятичную точку.

Создайте каждую меру отдельно.

~~~dax
Оборот = SUM(Items[price])
Заказы = DISTINCTCOUNT(Orders[order_id])
Средний чек = DIVIDE([Оборот], [Заказы])
Клиенты = DISTINCTCOUNT(Orders[customer_unique_id])
Доля опозданий = DIVIDE(CALCULATE([Заказы], Orders[is_late] == TRUE()), CALCULATE([Заказы], FILTER(Orders, NOT ISBLANK(Orders[is_late]))))
Средняя оценка = AVERAGE(Orders[review_score])
Срок доставки = AVERAGE(Orders[delivery_days])
~~~

На обзоре разместите шесть первых мер на карточках, графики оборота и заказов по purchase_month и столбчатую диаграмму по customer_state. На логистической странице выведите срок и долю опозданий, сравните штаты с минимум 100 известными датами и среднюю оценку по is_late.

Для страницы клиентов присоедините customer_rfm[segment] к Orders по customer_unique_id. Перед фильтрацией определите для каждого клиента месяц его первой покупки. Добавьте его к каждой строке заказа и вычислите расстояние в месяцах между ним и purchase_month. Строки матрицы — месяц первой покупки, столбцы — расстояние; числитель — число уникальных клиентов ячейки, знаменатель — число клиентов когорты в нулевом месяце. Будущие ячейки оставьте пустыми. Новых клиентов считайте по первой покупке. Для сегментов используйте число уникальных клиентов. Синхронизируйте срезы по страницам и сверьте основной обзор с sql/14_reconciliation.sql.

Готовая версия в репозитории выполнена в HTML и JavaScript. Эти шаги описывают самостоятельную сборку в Desktop.
