# Сценарии использования отчёта

Критерии ниже можно проверить на полной выгрузке. Месяц относится к дате покупки, штат — к адресу покупателя. Денежные суммы в бразильских реалах.

| Роль и цель | Что проверяет пользователь |
|---|---|
| Как менеджер продаж, я хочу видеть число заказов, товарный оборот и средний чек, чтобы понимать масштаб продаж. | 1. При сброшенных фильтрах обзор показывает 96 478 доставленных заказов и 13 221 498,11 R$ оборота (возможен округлённый формат). 2. При выборе месяца значения относятся к покупкам в этом месяце. |
| Как коммерческий менеджер, я хочу сравнить штаты, чтобы выбрать регион для разбора продаж. | 1. Фильтр штата относится к покупателю. 2. После его сброса восстанавливается выборка по всей Бразилии. |
| Как категорийный менеджер, я хочу сравнить категории, чтобы понять, какие товары дают основной оборот. | 1. При пустых фильтрах лидирует `health_beauty`. 2. Для выбранной категории в оборот попадает стоимость только её позиций, даже если у заказа была смешанная корзина. |
| Как клиентский аналитик, я хочу видеть повторные покупки, чтобы оценить удержание. | 1. Покупатель определяется по `customer_unique_id`. 2. Несколько товаров или платежей одного заказа сохраняют одну покупку при расчёте частоты. |
| Как руководитель логистики, я хочу находить опоздания, чтобы выбирать регионы для проверки доставки. | 1. Заказ, доставленный в обещанный календарный день, попадает в группу «в срок». 2. В знаменатель доли опозданий входят только доставленные заказы с известными датами. |
| Как менеджер клиентского опыта, я хочу сравнить оценки при двух исходах доставки, чтобы понять, где чаще возникают жалобы. | 1. Каждый заказ с известным сроком и отзывом получает один голос в своей группе. 2. При нескольких ответах используется последний по времени ответа. |
| Как аналитик, я хочу сверять цифры отчёта с SQL, чтобы находить ошибки после обновления данных. | 1. Без фильтров сумма стоимостей позиций равна GMV отчёта. 2. В витрине число строк равно числу уникальных `order_id`. |
