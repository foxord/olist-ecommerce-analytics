# Аудит качества

Аудит охватывает девять исходных CSV и все статусы заказов. Условия проверок и числители каждой доли доступны в [SQL-аудите Q1–Q6](../sql/03_quality_audit.sql). Аналитические показатели по доставленным заказам проверяются отдельно. [Определения метрик](metrics.md)

## Q1. Что повторяется

В orders, customers, products, sellers и category_translation лишних строк по выбранным ключам нет. То же верно для составных ключей позиций и платежей. Если ошибочно принять order_id за ключ позиции, получится 13 984 лишних строки, а платежа — 4 446. Обе таблицы содержат несколько событий одного заказа, поэтому сохраняем их на исходном уровне.

В отзывах review_id даёт 814 повторений сверх первого, order_id — 551. У 547 заказов несколько отзывов. Никакие исходные оценки не удаляем. В витрине берём один последний отзыв на заказ. Geo содержит 981 148 повторений префикса сверх первого и 261 831 полностью повторяющуюся строку по пяти исходным полям. Сделанный напрямую JOIN по префиксу размножил бы наблюдения. В географических отчётах используем штат/город из customers.

## Q3. Как JOIN завышает деньги

| Способ, все статусы | Товарные позиции, R$ | Оплаты, R$ |
|---|---:|---:|
| Каждая дочерняя таблица отдельно | 13 591 643,70 | 16 008 872,12 |
| orders JOIN order_items JOIN order_payments | 14 209 115,34 | 20 308 134,71 |

Позиции содержат дополнительно 2 251 909,54 R$ доставки. Платёж и цена товара описывают разные суммы, набор заказов тоже различается. Наивный JOIN выдаёт 117 601 строку. Например, две позиции и три платежа одного заказа дадут шесть строк. Сначала группируем каждую дочернюю таблицу по order_id, только после этого соединяем. Для GMV оставляем сумму цен товаров в доставленных заказах. [Витрина](../sql/04_order_mart.sql)

## Q4–Q6. Логика событий, справочники и допустимые значения

| Условие | Масштаб | Решение и влияние |
|---|---:|---|
| Получение раньше покупки | 0 | Длительность от покупки до получения неотрицательна. |
| Передача перевозчику раньше одобрения | 1 359 | Фиксируем аномалию. Для анализа времени этого этапа такие интервалы надо отбирать отдельно. |
| Получение раньше передачи перевозчику | 23 | Такие строки непригодны для расчёта времени именно у перевозчика. |
| Заказы без позиций / позиции без заказа / клиенты без заказа | 775 / 0 / 0 | Оставляем заказы в общей воронке. У всех доставленных есть позиции. |
| Заказ без платежа | 1 | SUM платежей у такого заказа остаётся NULL. Товарный оборот известен из позиций. |
| Категории без перевода | 2 категории, 13 товаров | 10 товаров в portateis_cozinha_e_preparadores_de_alimentos и 3 в pc_gamer. Сохраняем исходное название группы. |
| Цена ≤ 0 / отрицательная доставка | 0 / 0 | Минимальная цена позиции 0,85 R$. Отрицательных сумм оплаты тоже нет. |
| Нулевая доставка / нулевой платёж | 383 / 9 | Сохраняем наблюдения. Бесплатная доставка возможна, причина конкретного нулевого платежа неизвестна. |
| Число рассрочек равно нулю | 2 платёжные строки | Показываем отдельной группой при анализе числа взносов. |
| Вес равен нулю / неположительный габарит | 4 / 0 | Нулевой вес не использовать как физическое измерение. Максимальный вес 40 425 г, максимальные длина, ширина и высота — 105, 118 и 105 см. Редкие крупные значения сохраняем. |

Все восемь наблюдаемых статусов приведены в таблице Q2. Удаление покупок по отсутствию комментария, весу товара или технической аномалии одного этапа исказило бы независимые показатели.
